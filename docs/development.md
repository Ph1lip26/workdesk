# Workdesk 开发与维护

本页记录工程结构、验证和交付方式；使用行为见 [使用指南](usage-guide.md)，版本结果见 [CHANGELOG](../CHANGELOG.md)。维护授权以 [AGENTS.md](../AGENTS.md) 和本次用户指令为准。文档整理日期：2026-11-13。

## 1. 改动边界

- 先读现状、Git差异及相关文档；保存现有未提交改动，不拿旧备份覆盖新记录。修改前做库外备份，写后回读。
- 程序源码、已安装程序、私人运行数据和发布产物分开。仅改文档不应触碰业务代码、数据库、图标或运行配置，也不需要重启。
- `backend/analysis-instructions.md` 是模型运行指令，**不是普通说明文档**；修改它属于行为变更，需验证模型契约。`AGENTS.md` 是维护边界，第三方声明是许可记录，不能为了精简随意改写。
- 不接管用户日常浏览器，不强制杀进程，不清全局缓存，不改全局环境，不通过修改知识库／放宽校验来让测试过关。
- 发布和本机部署是两个动作；测试成功不等于已部署、已发布或用户已认可审美。

## 2. 目录与责任

| 路径 | 责任 |
|---|---|
| `desktop/main.cjs`、`platform.cjs`、`preload.cjs` | Electron 生命周期、平台集成、受限桌面桥接 |
| `desktop/setup.*` | 首次配置界面；不预置私人路径 |
| `backend/server.py`、`core.py` | 本地服务、任务编排和入库流程 |
| `backend/browser_worker.py`、`components.py`、`runtime.py` | 收藏浏览器、按需组件及运行依赖 |
| `backend/storage.py` | 本机持久化 |
| `backend/home.py`、`summaries.py` | 明确来源绑定、缓存摘要、证据及生成互斥 |
| `backend/purchases.py`、`health.py`、`illness.py` | 购买、体重、生病记录；各自保存／冲突边界 |
| `backend/action_ideas.py`、`media_cleanup.py` | 来源约束的行动候选、入库后的核验清理 |
| `backend/static/` | 页面、样式、模块交互和原版图标资源 |
| `assets/` | 通用发行品牌；不存私人 Logo |
| `scripts/`、`tests/` | 构建、隐私检查、隔离测试及维护工具 |
| `docs/github-actions/` | 工作流模板；不等于已经启用 CI |
| `build/` | 库外构建／测试产物，不能提交私人输出 |

版本号、入口和打包白名单以 `package.json` 为准；Python依赖用 `backend/requirements-lock.txt`，可选 GPU 依赖单列。程序不是“装上就同步所有设备”的服务；私人配置和登录独立迁移。

## 3. 不应被优化掉的约束

### 内容与数据

- 只读明确绑定的知识库来源，手动生成摘要才使用 Codex；保留证据、日期、用户决定与 AI 建议的差别。
- 不覆盖购买手动字段；健康同日冲突不覆盖，手动删除导入记录不复活；新功能不得破坏修订号和未保存保护。
- 作品使用精确 ID 与真实路径识别入库；部分采集不清空旧数据，失败保留可重试素材。
- 差量校对保留原文锚点、行号、时间戳和完整还原，禁止用摘要替代全文。图文仍逐张处理，视频画面仍明确为抽样。
- 中间素材必须先通过来源／笔记／哈希／引用核验，只删授权范围。未知、失败、活跃、被引用数据保留，不加自动清理任务。

### 界面与性能

- 首页精炼，常规六卡一屏，来源详情可达；不要以裁字、过细小字或堆模块换取形式上的简洁。
- 一级图标轨＋相连二级面板；首页无二级。文字实际字形、图标、主区换列、快速反向都要检查，容器透明度变化不代表文字动画已经正确。
- 黑夜用中性层次；白昼页面比卡片白。金属不靠脏颗粒／明显横纹，玻璃限适合的临时层；一级只有选中方框金属，二级保持纯色。
- 优先批量读写、可见区域动画、缓存及稳定节点；避免逐帧重排、静止时空跑、轮询重建整页。尊重减少动态效果、焦点和键盘操作。
- 任务栏图标、桌面快捷方式、窗口／托盘图标和应用内导航是不同对象；需求模糊先辨明位置，不联动改一整套。

## 4. Windows 构建与隔离验证

以下命令在**干净的项目副本根目录**执行；副本及产物放知识库外，使用自己的明确绝对工作路径，不从知识库根运行。需要 PowerShell 7、Node.js 22+ 及构建引导用 Python。

```powershell
npm ci
python scripts/prepare_runtime.py
npm test
python scripts/privacy_check.py --tracked
npm run package:win
node scripts/audit_payload.cjs build/dist/win-unpacked
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/native_smoke.ps1 -Payload build/dist/win-unpacked
```

准备脚本获取官方 CPython 并验证 SHA512，安装固定依赖；不要复制个人 venv、浏览器 Profile、模型、Codex 配置或私人品牌。载荷审计同时核对代码与资源，不把“压缩包成功生成”当作验收。

原生启动器使用隔离的 `build/native-test` 合成数据，检查已有测试进程后再准备夹具；不要并发重置同一个测试目录。它等待窗口检查结束并把输出落盘，避免开发脚本输出管道提前关闭造成 EPIPE；不吞掉其他异常或断言失败。

专项可通过 `-Scope` 选择 `health-sync`、`health-chart`、`health-hover`、`purchases`、`home-sort`、`rail-order`、`queue-style`、`motion-lifecycle` 等；可用值以启动器参数为准。新增模块还有独立的摘要、生病等测试脚本，按其启动条件运行，不能拿旧计数当本次结果。

### 验证层级

1. 静态差异、语法／逻辑测试及新增回归。
2. 隔离合成数据的界面／原生检查：状态、焦点、缩窗、快速反向、失败保留与无动效路径。
3. 打包载荷隐私与内容审计、空白配置和首次有效配置。
4. 从安装包提取载荷逐文件校验，确认发布的确是已测内容。
5. 有授权时做真实设备、真实登录和真实入库验证；不得冒充前四层已覆盖这一层。

保留失败日志和复测结果，不降低门槛来通过。合成样本的 token、耗时、Layout/Paint或临时内存改进不等于真实用户固定提速、整机内存下降或零掉帧。

## 5. 本机部署

部署前确认**当前**没有未保存编辑，所有相关后台任务空闲；备份所改文件和必要数据，核对并发修改。界面改动优先仅重载；后端／主进程改动通过正常退出再启动，不强杀浏览器或后台。

部署后核对实际提供的文件、进程及相关行为，比较记录／偏好，不能只确认源码已经写好。用户暂不允许重载时保留待启用状态，明确说未生效；不要沿用上一轮的旧许可。公开发布不自动部署到本机。

## 6. 隐私检查与发布

**默认只本机验证；阶段性成果先询问。用户说“上传”时，默认包含脱敏源码＋新 Windows 安装包＋SHA256；明确只传源码时按该次限定。** 不再要求额外确认“是否也打包”，但不因此自动安装、重启或上传私人资料。

发布步骤：

1. 确认本次授权、范围和已有未提交修改；公开内容只留通用代码、匿名资产、合成测试及文档。
2. 按现有忽略规则准备干净待发布副本，更新版本、CHANGELOG、README下载链接及相关使用说明。
3. 运行逻辑、完整源码隐私与载荷检查、原生及首次配置检查；审查 staged diff 与待发布文件清单。工作目录有私人产物时使用干净副本，**不改门禁、不删除别人的文件来通过检查**。
4. 确认安装包与已测载荷一致，生成同版本 SHA256；再提交／推送、打标签并发布 installer 和校验文件。只上传明确产物，不上传构建日志、测试截图或原始运行目录。
5. 回读远端提交、Release资产及校验值，报告源码、安装包、本机部署分别处于什么状态；上传失败不能说已同步。

`scripts/sync.ps1 -Message "更新说明" -ConfirmUpload` 是授权后的源码同步工具，不能单凭它声称安装包也已更新；发布仍需完成上述流程。不设自动上传任务或 Git 检查钩子。

禁止公开：个人路径、账号、令牌、Cookie、真实收藏 ID、知识库内容、购买／健康记录、日志、截图、模型缓存、私人品牌和配置。`--tracked` 检查用于已跟踪文件；发布时还需检查新增文件、完整干净副本及载荷。公共包中通用 W 与私有图标覆盖保持分离。

## 7. CI、Mac 与许可

仓库保留 `ci.yml`、`release.yml`、`mac-test.yml` 模板在 `docs/github-actions/`。2026-11-01 的记录显示当时凭证缺 workflow 权限、模板未启用；这是历史状态，不替代下次发布时重新检查。只有放入 `.github/workflows/` 并实际运行成功才有对应 CI 结果，不因有模板就宣称已自动构建。

Mac 需真正 macOS 主机，不能拿 Windows Python 或 Windows 回归结果冒充，接续见 [Mac 测试版](mac-preview.md)。签名、公证、真机验收未交付时必须明说。

第三方许可见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)，保留随包许可证。项目未提供统一开源许可证；公开源码不等于所有内容可任意再分发。

## 8. 文档维护方式

后续修改更新对应章节，不在每篇末尾追加一套完整流水账。旧“待启用／未发布”在生效后转为有日期的历史事实；保留必要证据和未验证范围，不混入现行操作说明。
